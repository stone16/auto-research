Three phase invariants
  1. Freeze is one-way. Draft → Active legal. Active → Draft illegal. Never.
  2. Complete is terminal. No transitions out except fork-to-new-Node. "Oops we weren't done" → create a new child to capture the gap, never revert.
  3. In-Review is an execution barrier. No new Run dispatches allowed while a Node is In-Review. This is what makes human review align with a frozen artifact snapshot rather than a moving target.
Logic notes
  • Phase is not decoration. It's an execution gate. Dispatching a research_iteration Run to a Draft Node is a data-layer error, not a policy error.
  • Born-structured children skip Draft. When a parent in Active spawns children via its acceptance, those children enter Active directly with acceptance inherited from the parent.
  • Complete and Archived are both terminal but distinct. Complete = "did it." Archived = "stopped doing it." Failure is an archived_reason, not a separate phase.
  • In-Review blocks the execution layer, not the editor. You can still add human notes, drill into past Runs, leave feedback. You just can't mutate contract or start new work until the review resolves.

A conversational schema builder, not a form. Agent proposes each item with reasoning. User can edit, reject, append, skip, pause, or reset at any point. Session state persists across pauses.

Logic notes
  • Every proposal carries reasoning that cites specific doc sections. The agent cannot propose in the dark; it must tie each item to evidence (prose, parent context, foundations invariants). This is the same judge-with-evidence pattern used in production LLM eval.
  • Six user interruption actions are first-class: Accept / Edit / Reject / Append own / Skip layer / Pause / Reset. None of these is an edge case.
  • Pause persists partial state. On resume, the agent does a fresh read of Node docs plus the partial schema. Already-confirmed items are not reopened. This keeps the session idempotent across time.
  • Sessions progress layer by layer: assertions → metrics → rubric → done_when. User can "skip this layer" if the Node doesn't need that dimension.
  • This is a UX commitment, not a polish detail. Without co-authoring, the freeze becomes a giant form, users avoid it, and the whole structured-acceptance pillar collapses.

Logic notes
  • Scratchpads are physically disjoint directories. No git conflicts are possible because sub-Runs never touch each other's files.
  • Returns are typed records, not prose blobs. The primary agent reasons over {findings, concerns, confidence, needs_human_review}, a fixed 4-field schema. It never has to parse natural language.
  • Synthesis is the parent agent's reasoning, not an algorithm. There is no merge function. The agent writes a synthesis reasoning log that describes what it kept, merged, discarded, and why.
  • Escalation is agent-driven. sub-Run-C's needs_human_review bubbled up because Run-P-2's agent chose to promote it. Had Run-P-2's agent decided the concern was already handled, it could have suppressed the flag. No structural promotion rule.
  • Sub-Runs are invisible by default. Users never see A/B/C unless they explicitly drill into Run-P-2. This protects the "user only faces Node tree" commitment.

Contract change reconcile — timeline

What happens when a user edits acceptance (or local_policy, or intent) while a Run is in-flight. Three possible outcomes: continue, abort, or restart.

14:00 ●

Logic notes
  • Contract edits do NOT block. User can edit freely even with in-flight Runs. This preserves "human always in control."
  • The Run's agent decides the outcome, not the system. Continue / abort / restart is reasoning, not a rule table. Agent is closest to the actual state and most competent to judge.
  • Reconcile applies to all contract fields, not just acceptance. Editing local_policy triggers the same protocol. This generalization is the direct consequence of Task #10's lock.
  • Every reconcile decision is an audit_trail event. Three months later, opening this Run shows what contract it was dispatched against, what the new contract was, and why the agent continued / aborted / restarted.
  • No silent version forks. The Node keeps its single identity; it does not split into "v1 branch" and "v2 branch." Soft-fork was considered and rejected because it turns the OKR tree into a version tree.
