## Q1 - SEO/GEO Architecture

Pattern hypothesis: build SEO/GEO as UI -> domain adapter/tools -> AI/recommendation service, but put identity, sessions, credentials, ledgers, schedules, and kill-switches in shared Core rather than inside the SEO engine. `getuai-seo` explicitly uses the three-layer split: UI layer, MCP SEO tools/API integration layer, and AI backend for processing/recommendations (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-seo.md:7-11`, `:93-97`). The shared session/data plane comes from `getuai-api`, which is the central FastAPI API layer and source of truth for sessions, temporary image/text storage, validation, and cleanup (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-api.md:7-28`).

Components and data flow: crawler/sensor inputs enter through tool endpoints such as site structure, Google Search, competitor discovery, keyword ideas, URL content analysis, and keyword clustering (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-plugin.md:11-20`, `:117-126`). Ranking signal source is split between explicit SEO metrics/keyword tracking in `getuai-seo` (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-seo.md:101-106`) and generated indexability assets in `rankncompare`, where sitemap, robots, SEO metadata APIs, and JSON data storage serve as content store and publisher surfaces (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/rankncompare.md:28`, `:53-56`, `:128-149`). External dependencies are search APIs, Google Ads keyword APIs, LLM providers, CMS/static publishing, and app storage. The SEO repos disagree on orchestration: `getuai-seo` is a running three-service product, `rankncompare` is a static/data-store SEO publisher, and `growth-engine-legacy` says Browser -> Core only, engines never see raw Logto tokens, and Core owns platform facts (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/growth-engine-legacy.md:43-50`). Recommendation: keep the domain tools, but require human-in-loop approval, override, and kill-switch in Core action/schedule ledgers before publish or recurring ranking checks (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/growth-engine-legacy.md:83-88`).

## Q2 - Content Writing Architecture

Pipeline: ideation starts from campaign/entity facts, recipients, search or social intent; outline/draft are LLM-generated; edit is human and rule based; publish sends email, web, or channel output; post-publish reads outcomes back into the next run. `getuai-email-2.0` has the clearest concrete content pipeline: Campaign CRUD, Recipients CRUD/CSV import, SMTP account CRUD/test, Batch create + AI generate + send (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:70-73`). Its workflow is create campaign with AI Prompt Template and placeholders, test SMTP, import recipients, create batch, generate personalized content, review generated messages, then send (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:91-118`).

LLM role by stage: generator for personalized drafts (`Azure OpenAI gpt5-mini`), critic/retriever where web search citations are required, and orchestrator only when it selects recipients and batches. The load-bearing choices are style guide injection through prompt template variables, recipient schema, mandatory SMTP connection test, human review before send, and storage/session contracts inherited from `getuai-api` (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:14`, `:91-99`, `:111-118`; `runs/growth-engine-from-scratch/sources/_raw/getuai-api.md:24-40`). Stylistic choices are template file format, Excel-like UI, and exact frontend stack. Disagreement: email content is structured around recipients and SMTP; OpenClaw-style content skills support multi-modal generation/transcription/summarization as reusable channel skills (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:153`, `:5104-5152`, `:6656-6716`).

## Q3 - Ads Architecture

The converged ads loop is campaign feed -> bidding/budget/targeting -> reporting -> attribution -> optimization. `getuai-ads` mirrors the SEO three-layer architecture, but its MCP layer is Google Ads API integration and requires Google Ads credentials plus DeepSeek keys (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-ads.md:7-11`, `:24-28`, `:66-100`). `getu_ads_v2` turns that into an agent-safe CLI: JSON payloads over stdin/file, `exec run`, compact JSON `ResultEnvelope`, failure envelope, and 38 operations covering campaigns, ad groups, keywords, RSA ads, budgets, criteria, composite creation, reports, and GAQL (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getu_ads_v2.md:9-67`, `:1010-1017`).

Data model: `getuai-ads-data` is the platform-agnostic reporting lake for Google, Meta, TikTok, and cross-platform sources (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-ads-data.md:7`, `:15`, `:159-164`). It names campaign fields and conversions across platform tables (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-ads-data.md:216-250`). Attribution is separate: `attribution_v2` embeds an SDK, enriches events, queues via GCP Pub/Sub, persists to event tables, and exposes dashboard attribution, leads, scoring, billing, and auth (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/attribution_v2.md:13-16`). The boundary is: platform SDKs and mutation commands stay platform-bound; query schemas, ResultEnvelope, attribution events, anomaly banners, pacing decisions, and kill-vs-scale criteria are platform-agnostic. Human-in-loop is the read/write skill boundary in `lawyer_marketing`: analysis agents get read-only query skills, and write operations are blocked by skill docs plus code hooks (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/lawyer_marketing.md:248-269`).

## Q4 - Social Architecture

Social decomposes into listen, post, schedule, engage, and monitor, but the corpus has adapters more than a single clean social abstraction. Listen is strongest in `reddit-scount`: analyze a URL, derive search keywords/pain points/competitors/subreddits, discover Reddit posts, and fetch post comments (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/reddit-scount.md:108-121`, `:124-181`). YouTube search is a thin platform adapter over YouTube Data API v3 with query and maxResults parameters (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/youtube-api-demo.md:7-20`, `:48-54`). X/Twitter post/reply/search is present as an OpenClaw `xurl` skill (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:7392-7422`, `:7502-7507`).

OpenClaw is the closest multi-platform abstraction: a Gateway control plane, multi-channel inbox, routing, sessions, tools, cron/webhooks, and per-channel adapters for WhatsApp, Telegram, Slack, Discord, Google Chat, Signal, Teams, Matrix, Feishu, LINE, Twitch, X-like tools, and WebChat (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:132-158`). Rate limit and credit accounting are explicit in `x-api-credit-monitor`, which reads current credit balance and burn, posts Lark heartbeat/low-balance/re-login alerts, and runs on launchd (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/x-api-credit-monitor.md:7-17`, `:72-104`). Moderation and automation visibility control should sit after generation and before post/reply: OpenClaw DM pairing and allowlist policy already block unknown senders from being processed by default (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:122-126`).

## Q9 - SEO/GEO Cognition

1. Topical authority. Decision shaped: build a durable entity/category content store before asking an LLM to produce SEO copy. Trigger condition: the target has stable categories, products, or comparison terms that search engines can crawl repeatedly.
   - Worked here: `rankncompare` turns category/product data into sitemap, robots, category priority, canonical URLs, structured data, FAQs, and internal links, so authority is materialized as crawlable structure rather than only prose (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/rankncompare.md:128-157`, `:163-187`).
   - Failed here: `getuai-2.0` is a frontend/Gemini AI Studio scaffold with no crawlable content store, sitemap, ranking sensor, or SEO data contract, so the authority model has nowhere to persist (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-2.0.md:15-43`).
2. Intent mapping. Decision shaped: map query intent to crawl/search/keyword-clustering tools before choosing generator prompts. Trigger condition: the team is deciding which pages, keywords, competitors, or clusters deserve content.
   - Worked here: `getuai-plugin` exposes Google Search Analyzer, Competitor Discovery, Keyword Ideas, URL Content Analyzer, and Keyword Clustering as explicit SEO intelligence tools with API endpoints (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-plugin.md:15-20`, `:121-126`).
   - Failed here: `rankncompare` can publish indexable category pages, but its documented SEO layer is sitemap/meta/internal-link generation, not SERP intent discovery; using it alone would confuse a known taxonomy with live intent mapping (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/rankncompare.md:132-157`, `:183-187`).
3. E-E-A-T through vertical evidence. Decision shaped: inject domain references, compliance rules, benchmarks, and competitor facts before generating recommendations. Trigger condition: the domain has regulated claims, high CPC, or expertise-sensitive buyer trust.
   - Worked here: `lawyer_marketing` injects legal practice-area profiles, compliance, budgets, keyword strategy, ad copy, and legal CPC/CTR/CVR benchmarks into the marketing agent (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/lawyer_marketing.md:271-304`, `:307-313`).
   - Failed here: the greenfield `growth-engine` recognizes industry packs as the mechanism for domain difference but is still pre-implementation, so E-E-A-T remains a documented dependency until industry packs and engine slices land (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/growth-engine.md:7-13`, `:25-30`).
4. GEO vs SEO pivot. Decision shaped: separate search-engine indexability from LLM-answer visibility. Trigger condition: success depends on whether ChatGPT/Claude/Gemini mention the product, not only whether Google indexes the URL.
   - Worked here: LLMRush measures rank, sentiment, reviews, and model-by-model comparison across ChatGPT, DeepSeek, Claude, Gemini, and other LLM providers (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/LLMRush.md:7-23`).
   - Failed here: `rankncompare`'s sitemap/robots/canonical/FAQ work is strong SEO infrastructure but has no LLM answer-inclusion evaluator; treating sitemap success as GEO success would overclaim (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/rankncompare.md:134-157`).
5. Content velocity vs depth. Decision shaped: ship repeatable surfaces only after the content store, retrieval inputs, and evaluation sensor exist. Trigger condition: the team can publish faster than it can validate ranking, attribution, or answer inclusion.
   - Worked here: `getuai-seo` keeps content optimization, keyword tracking, performance metrics, and backlink/competitor analysis inside a three-layer UI/MCP/AI architecture, giving velocity a measurement loop (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-seo.md:7-11`, `:93-106`).
   - Failed here: prototype-only scaffolds such as `getuai-2.0` can generate AI output quickly, but the documented structure stops at frontend services and Gemini setup, so there is no evaluator or durable SEO artifact to keep velocity honest (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-2.0.md:19-43`).
Anti-patterns: tool-first SEO with no content store; sitemap-as-GEO-evaluator; content velocity without rank/LLM-answer sensors; generic expertise claims without vertical evidence; treating a prototype generator as a publishing engine.

## Q10 - Content Writing Cognition

1. User journey mapping. Decision shaped: bind each writing artifact to a recipient, campaign, channel, review step, and send/publish action. Links to Q2: content architecture must include ideation -> draft -> review -> publish. Links to Q6: `campaign-prompt-template`, `recipient-import`, `personalized-email-draft`, and `smtp-test-and-send` are the skill embodiment.
   - Worked here: `getuai-email-2.0` walks campaign creation, prompt variables, SMTP test, recipient import, batch creation, AI generation, review, and send as one journey (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:89-118`).
   - Failed here: `gmi-prototype` guides a user through model selection, video count, free-form prompt, and local file save, but it does not attach the output to a campaign, audience, review, publish, or outcome loop (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/gmi-prototype.md:36-50`).
2. Content portfolio theory. Decision shaped: maintain a portfolio of reusable text, image, video, and summary assets with metadata instead of isolated one-off generations. Links to Q2: post-publish iteration needs asset identity. Links to Q6: `image-text-composer`, `summarizer-transcriber`, and artifact-store requirements exist because portfolio items must be findable.
   - Worked here: Visionary treats generated image/video assets as an organized library with folders, automatic analysis, metadata tagging, and brand-protection guardrails (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/Visionary.md:11-27`, `:37-42`).
   - Failed here: `gmi-prototype` saves generated videos automatically under `./generated_videos/`, which proves generation works but leaves the asset outside tenant/run/campaign ownership (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/gmi-prototype.md:11-16`, `:48-50`).
3. Distribution over production. Decision shaped: prefer skills that deliver or route content to a channel over skills that only produce media. Links to Q2: publish is load-bearing, not an afterthought. Links to Q6: retrieval grounding and SMTP/send skills are more from-scratch-critical than a prettier generator.
   - Worked here: `getuai-email-2.0` requires SMTP account testing, recipient import, batch creation, generated-content review, and email send, so production is coupled to distribution (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:96-118`).
   - Failed here: OpenClaw's image generation skill can produce galleries and files, but by itself it is an asset generator; without a campaign/channel binding it does not complete distribution (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:5104-5152`).
4. ROI time window. Decision shaped: define when a content artifact is evaluated, and by which sensor, before scaling production. Links to Q2: post-publish iteration is a required stage. Links to Q6: `multi-model-rank-summary` and retrieval-grounded copy are evaluation-adjacent skills.
   - Worked here: LLMRush keeps search history, rank, sentiment, positive/negative reviews, token usage, authentication, structured logging, and request IDs, which gives content/GEO work a measurable window beyond one draft (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/LLMRush.md:7-23`).
   - Failed here: the documented `getuai-email-2.0` flow ends at send; it has review and distribution, but no cited open/click/reply/conversion feedback loop in the core flow, so ROI-window discipline must be added through shared attribution (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:111-118`).
5. Brand voice as forcing function. Decision shaped: encode voice and tone as variables, templates, references, and review gates rather than relying on free-form prompt taste. Links to Q2: style-guide injection is load-bearing. Links to Q6: prompt template variables and human review are the anti-drift controls.
   - Worked here: `getuai-email-2.0` requires an AI Prompt Template with `{email}`, `{first_name}`, `{last_name}`, `{company}`, and `{position}` placeholders, grounding voice in recipient/campaign data (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-email-2.0.md:91-94`, `:111-117`).
   - Failed here: `gmi-prototype` asks for a custom prompt and saves media output, but the cited workflow has no reusable brand voice schema, reviewer rule, or recipient variables (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/gmi-prototype.md:46-50`).
Anti-patterns: production-over-distribution; prompt-only voice with no variables; no ROI window after send; asset files without campaign ownership; media generation treated as a content engine.

## Q11 - Ads Cognition

1. LTV/CAC discipline. Decision shaped: scale only when cost, conversion, and vertical benchmark evidence agree. Conditions where it holds: campaign reports expose conversion economics and the industry pack supplies benchmark priors.
   - Worked here: `lawyer_marketing` injects budget strategy, keyword strategy, ad copy, compliance, and CPC/CTR/CVR legal benchmarks, while `getu_ads_v2` reports cost, conversions, CTR, average CPC, and cost_per_conversion per campaign (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/lawyer_marketing.md:291-304`; `runs/growth-engine-from-scratch/sources/_raw/getu_ads_v2.md:1048-1064`).
   - Failed here: it breaks as true LTV/CAC when attribution identity is missing: `attribution_v2` warns that missing `setUserId` leaves known-user lead rows absent, and session rotation changes attribution semantics across users (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/attribution_v2.md:117-119`, `:153-162`).
2. Pacing logic. Decision shaped: change budgets gradually and only through validated daily-budget operations. Conditions where it holds: budgets are explicit operation payloads with bounded amount fields and a campaign id.
   - Worked here: `getu_ads_v2` exposes `search.budget.update` with `campaign_id` and `amount` fields, 1-100 updates, and daily-budget semantics (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getu_ads_v2.md:1127-1149`).
   - Failed here: the same raw budget operation can mutate spend without conversion-confidence or approval context; the corpus therefore needs the `lawyer_marketing` Plan-Validate-Execute boundary and action logging before budget pacing is safe (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/lawyer_marketing.md:244-269`).
3. Creative fatigue curves. Decision shaped: evaluate ad-level performance and rotate creative only when the ad/keyword/campaign breakdown shows fatigue rather than account-level noise. Conditions where it holds: reports are granular enough to isolate ad and search-term performance.
   - Worked here: `getu_ads_v2` provides ad-level reporting and search-term reporting with date range, campaign/ad-group filters, impressions, clicks, cost, conversions, CTR, average CPC, and cost_per_conversion (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getu_ads_v2.md:1066-1105`).
   - Failed here: composite campaign creation preserves campaign/ad groups even if RSA ad creation fails for policy reasons, so creative iteration cannot assume every generated ad actually shipped; fatigue analysis must distinguish live ads from failed creative mutations (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getu_ads_v2.md:630-704`).
4. Attribution paradox. Decision shaped: do not trust platform-reported conversions alone, but also do not trust first-party attribution unless session and identity wiring are correct. Conditions where it holds: browser SDK, event ingestion, queues, dashboard aggregation, and user/session semantics are wired end to end.
   - Worked here: `attribution_v2` splits SDK, event ingress/consumer, dashboard API, frontend, UTM capture, lead extraction, scoring, billing, and auth into a production attribution stack (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/attribution_v2.md:13-23`, `:147-162`).
   - Failed here: cookies on public suffixes, missing `setUserId`, immediate-vs-batched event mistakes, and session rotation are all explicit landmines that silently corrupt attribution windows (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/attribution_v2.md:117-119`, `:151-155`).
5. Kill-vs-scale criteria. Decision shaped: kill on policy, envelope, credential, attribution, or conversion-confidence failures; scale only after read-only analysis, validation, execution, and action logs agree. Conditions where it survives platform change: query/read skills remain separate from mutation/write skills.
   - Worked here: `lawyer_marketing` uses Plan-Validate-Execute, Pydantic validation, `ResultEnvelope`, action logging, operation-tier classification, and PreToolUse enforcement to keep analysts read-only and execution agents write-scoped (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/lawyer_marketing.md:244-269`).
   - Failed here: platform/API or credential drift still breaks execution if credentials are external to the action layer; `getuai-ads` requires Google Ads credential paths, developer token, login customer id, and DeepSeek keys before the subsystem can run (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/getuai-ads.md:21-28`).
Anti-patterns: scaling from platform UI metrics alone; budget mutation before attribution confidence; creative reporting that ignores failed ad creation; analyst agents with write tools; CAC claims without session/user identity.

## Q12 - Social Cognition

1. Platform game theory. Decision shaped: treat each platform as a different game with its own discovery surface, identity, quota, and reply semantics. Trigger condition: a generic post idea must choose Reddit, YouTube, X, Slack, or another channel.
   - Worked here: `reddit-scount` starts from target audience, pain points, competitors, target subreddits, keyword search, competitor discussions, and post comments, which matches Reddit's community/search game (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/reddit-scount.md:124-181`).
   - Failed here: a thin YouTube demo exposes keyword search and maxResults only; it is useful as a platform adapter, but it does not encode Reddit-style community context, X reply semantics, or multi-platform tone rules (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/youtube-api-demo.md:7-20`, `:48-54`).
2. Algorithm preference modeling. Decision shaped: model the observable ranking/recommendation signal before deciding content format or cadence. Trigger condition: the team wants to optimize for feed/search visibility rather than merely publish.
   - Worked here: YouTube's adapter makes search query and result count explicit, while Reddit Scout rotates keyword indexes and batches searches, giving each platform a visible discovery mechanism (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/youtube-api-demo.md:48-54`; `runs/growth-engine-from-scratch/sources/_raw/reddit-scount.md:141-172`).
   - Failed here: OpenClaw's multi-channel Gateway can route sessions, channels, cron, and tools, but the shared gateway is not itself an algorithm model for any platform feed; channel-specific sensors still need to stay isolated (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:132-158`, `:167-180`).
3. Community fit before brand voice. Decision shaped: infer audience language and pain before rewriting in a brand tone. Trigger condition: the source is a forum/community thread or competitor discussion.
   - Worked here: `reddit-scount` derives company description, target audience, pain points, competitor names, and target subreddits before discovery, so voice follows community fit (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/reddit-scount.md:124-139`).
   - Failed here: `xurl` supports direct post/reply/quote/search commands; without an upstream community-fit gate, it can publish brand voice into the wrong thread because the CLI contract only requires text/post_id/query (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:7388-7422`, `:7498-7507`).
4. Viral mechanics. Decision shaped: use reply, quote, search, timeline, and comment surfaces to find distribution loops, but do not confuse those mechanics with durable strategy. Trigger condition: a social lane asks whether to engage, amplify, or schedule.
   - Worked here: `xurl` exposes post, reply, quote, delete, read, search, user lookup, and timeline commands, which are the primitive mechanics needed for X-style engagement loops (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:7498-7510`).
   - Failed here: `youtube-api-demo` only searches and displays videos; it has no schedule/post/comment/reply loop, so it cannot validate viral mechanics beyond discovery (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/youtube-api-demo.md:11-20`, `:48-54`).
5. Automation visibility cost. Decision shaped: hide or constrain automation where users expect human context, and surface automation only where operations/monitoring require it. Trigger condition: an agent is about to reply, post, batch-send, or route messages across channels.
   - Worked here: OpenClaw uses channel routing, group mention gating, reply tags, per-channel chunking, retry policy, typing indicators, presence, usage tracking, model failover, and session pruning to keep automation behavior channel-aware (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:152-158`, `:175-180`).
   - Failed here: X automation has visible operational failure modes: the credit monitor must detect low balance and expired Chrome sessions, and `xurl` can post/reply directly if not wrapped by moderation/approval, so automation cost appears as quota exhaustion, re-login alerts, or spammy direct replies (tier: file:line `runs/growth-engine-from-scratch/sources/_raw/x-api-credit-monitor.md:12-18`; `runs/growth-engine-from-scratch/sources/_raw/openclaw-marketing.md:7500-7507`).
Anti-patterns: one tone across platforms; posting before listening; assuming a gateway equals a platform strategy; ignoring quota/session monitors; raw post/reply CLIs without moderation and community-fit gates.

Decision rule: share a component if it enforces tenant trust, credentials, schedules, ledger/audit, observability, LLM routing, or approval across more than one domain; isolate it when its schema, external API, ranking logic, tone, or kill criteria are domain-specific.

Worked example: attribution events are shared, while ranking logic stays domain-isolated. Attribution events are shared because the same browser SDK/session/event path turns ads clicks, content forms, and downstream leads into a cross-domain conversion record (`attribution_v2.md:13-16`, `:153-162`). The shared contract is event name, tenant/company, session_id, tracking_user_id, UTM/source, payload, and dispatch semantics; Ads consumes it for CAC and scale/kill decisions (Q7 `attribution-ingest`), Content consumes it for post-publish outcome loops (Q6 campaign/email flow), and Core observes it for ledgers (Q15 attribution/session breakage). Ranking logic stays isolated because `rankncompare` implements sitemap/category/indexability publishing (`rankncompare.md:128-157`) while LLMRush implements multi-model rank/sentiment sensing (`LLMRush.md:7-14`); neither should become a shared primitive for Ads bidding or Social posting. Core may standardize the metric envelope, but the SEO/GEO engine owns rank interpretation and evaluator logic.
